 THE ONE-SENTENCE VERSION
   Everything reduces to: find the single oxygen fugacity at which the total oxygen demanded by
   all six sinks equals the budget available. Every other quantity is read off from that fO2.
   (Six with `melt_H2` on; five otherwise — melt H₂ is opt-in, see PART D.)


===============================================================================================
 PART A — THE SHAPE OF THE PROBLEM (why the algorithm looks the way it does)
===============================================================================================

  Five reservoirs can host excess oxygen:

      solid Fe₂O₃   |  melt Fe₂O₃  |  melt CO₂  |  solid carbonate  |  C-O-H fluid

  They are not independent. At equilibrium all coexisting phases share ONE oxygen fugacity.
  So instead of solving for five loadings, the model solves for that shared fO2 and lets each
  sink report how much oxygen it would hold at it.

  This inverts the naive formulation:

      NAIVE      unknowns = the loadings; equations = "all phases must agree on fO2"
      THIS MODEL unknown  = fO2;          equation  = "the loadings must add up to the budget"

  Consequences that the rest of the algorithm depends on:

    1. fO2 EQUALITY IS AUTOMATIC. An unsaturated sink is *defined* as the loading whose own
       oxybarometer reads the shared fO2. There is no equation to satisfy — it holds by
       construction. It can only fail for a sink pinned at a physical end (full, or empty),
       which is correct: a phase holding no Fe³⁺, or all of it, no longer buffers anything.

    2. THE ROOT IS GUARANTEED. Every sink holds more oxygen as fO2 rises, so total demand is
       monotone. Far enough reduced it falls below the budget; far enough oxidised every sink
       saturates. A monotone function crossing a constant has exactly one root.

    3. THE OUTER SOLVER CAN BE TRIVIAL. The residual is 1-D, monotone and bracketed, so plain
       bisection suffices: no Jacobian, no initial guess, no divergence. That matters because
       the residual is often near-vertical where sinks saturate, and because the solid branch is
       a TABLE — piecewise linear in u, so its derivative is a step function and a bare Newton
       can cycle across a node boundary.
       ! THE INNER SOLVES ARE DIFFERENT and are NOT bisections. aC and the hydrogen split have
         smooth analytic residuals with no table in them, so both use a bracketed Illinois
         (regula-falsi) root find: superlinear, and it still cannot leave the bracket. Measured
         16-17 carbon-demand evaluations against the old fixed 120. See C.6.

  ! ASSUMPTION THAT MAKES (2) AND (3) WORK: monotonicity. It is enforced, not assumed — see B3.


===============================================================================================
 PART B — THE ALGORITHM, STEP BY STEP
===============================================================================================

 ENTRY: partition_Oₑₓ(P, T, p, ϕ, TOex, TC, H; ...)          [partition_Oₑₓ:786]

-----------------------------------------------------------------------------------------------
 B1. BUILD THE BULK COMPOSITION                              [endmember_composition:144]
-----------------------------------------------------------------------------------------------
     p -> mix harzburgitic and basaltic endmembers -> X (solid), XB (melt)
     ? p = 0 gives depleted solid, p = 1 enriched. Linear mixing, no phase logic.

-----------------------------------------------------------------------------------------------
 B2. CONVERT INPUTS TO ABSOLUTE BUDGETS                      [mass_budget:155, called at :791]
-----------------------------------------------------------------------------------------------
     Reference cell mass Mt = 1 kg in grams                                            [:790]
       Mf   = ϕ·Mt        melt mass
       Ms   = (1-ϕ)·Mt    solid mass
       Mc   = TC·Mt       carbon mass
       Mh   = H·Mt        free water mass
       TOₑₓ = TOex·Mt     the oxygen budget everything is measured against
     Also precomputed:
       molfracXB, nB_per_mass   melt oxide moles                                       [:162-163]
       Φ = 2·mm.O·molMf/TOₑₓ    converts a melt XCO₂ into a fraction of TOₑₓ            [:170]

     ? EARLY EXIT: TOₑₓ == 0 -> nothing to partition, return zeros.                     [:793]

     ! REFERENCE STATE, imposed here and used consistently by every sink downstream:
       excess oxygen is measured against Fe as FeO, C as graphite/diamond, H as H₂O.
       Hence 0.5 O per Fe³⁺, 2 O per CO₂ carbon, 2 O per carbonate carbon, and ZERO for water —
       the oxygen arriving bonded inside H₂O is not part of TOₑₓ and counting it would
       double-count it. This single choice is why the fluid term can come out NEGATIVE (see B7).

-----------------------------------------------------------------------------------------------
 B3. BUILD THE SOLID OXYBAROMETER                            [solid_fO2_interpolant:212]
-----------------------------------------------------------------------------------------------
     This is the only step that calls MAGEMin, and it happens ONCE per solve, before any
     iteration. The result is a cheap 1-D function sfO2(sOₑₓ).

     a) Scan Fe³⁺/ΣFe from 1e-5 to Rmax in nr steps                                    [:218]
     b) For each ratio, oxidise the bulk and record the resulting wt-fraction O          [:222-226]
     c) One batched MAGEMin call at (P,T) for all those compositions                    [:230]
     d) Re-express the x-axis: wt-fraction O  ->  fraction of the TOₑₓ budget            [:233]
        (so the table's x-axis is already in the same units as the unknown sOₑₓ)

     ? DROP FAILED POINTS: MAGEMin may not converge at some ratios; non-finite fO2 rows are
       removed and a warning is issued.                                                 [:237-241]

     ? REPAIR NON-MONOTONICITY:                                                         [:249-254]
       If fO2 does not rise monotonically with Fe³⁺ — which is what a change in the stable
       assemblage looks like, and is most likely at low P/T — the inversion in B6 becomes
       ill-posed and the guaranteed root can vanish. Repaired by isotonic regression
       (pool-adjacent-violators, [_isotonic:180]), the least-squares monotone fit, so points
       already in order are untouched. A warning fires.
       ! Pooling creates TIED values, and a flat segment is as damaging as a dip (the loading
         reading a given fO2 stops being unique), so a negligible strictly-increasing ramp
         breaks the ties.                                                               [:198-205]

     e) EXTRAPOLATE BEYOND BOTH ENDS                                                    [:258-283]
        Flat extrapolation is qualitatively wrong at both ends, so the oxybarometer's own
        log-linear form in Fe³⁺/Fe²⁺ is used instead, slope 1/0.1917:
          below the table   fO2 -> -inf as Fe³⁺ -> 0
          above the table   fO2 -> +inf as Fe²⁺ -> 0, written R/(1-R) so it diverges at the
                            STOICHIOMETRIC limit, not at the edge of sampling
        ! This is why the solid ceiling is stoichiometric rather than sampling-limited, and
          why `capacity_exceeded` stopped being an artefact of how far MAGEMin was sampled.
        Returns (sfO2, table_lo, table_hi, was_monotonic) so the report can flag extrapolated use.

-----------------------------------------------------------------------------------------------
 B4. COMPUTE THE PHYSICAL CEILINGS                           [partition_Oₑₓ:804-808]
-----------------------------------------------------------------------------------------------
     maxsOₑₓ  = every Fe²⁺ in the SOLID oxidised                                        [:804]
     maxmOₑₓ  = every Fe²⁺ in the MELT oxidised                                         [:807]
     maxXCO₂  = all carbon dissolved in the melt (reported, not imposed)                [:808]

     ! DELIBERATELY NOT CLIPPED AT "100 % of the budget". That clip looks harmless but it is
       the mass-balance constraint, which is already THE equation being solved. Imposing it
       twice makes a sink stop tracking fO2 for a bookkeeping reason and silently breaks the
       fO2 equality the whole model rests on.

-----------------------------------------------------------------------------------------------
 B5. SOLVE                                                   [bisect_solve:759, called at :821]
-----------------------------------------------------------------------------------------------
     Bisect on the shared log₁₀fO2 over the bracket [-120, +40].                        [:821]
     ? The bracket is far wider than any physical value on purpose: every demand saturates
       outside its own range, so it only has to straddle the root — it is not a constraint.

     ? CONVERGENCE IS JUDGED ON THE RESIDUAL ALONE.                                     [:776]
       A collapsed bracket with |F| still large means the residual is DISCONTINUOUS there and
       no root exists; reporting that as success would hand back sink shares that do not sum
       to 1. tol = 1e-8 sits above bisection's ~1e-11 precision floor and far below the
       ~0.1-3.5 jump at a genuine discontinuity.

     ? NO SIGN CHANGE ANYWHERE -> `capacity_exceeded`: even with every sink full the assemblage
       cannot hold the budget. Returns the closer endpoint, unconverged.                [:762-764]

     ? WHY THE OUTER STAYS BISECTION while the inner solves became Newton: the solid sink is a
       bilinear TABLE, so d(demand)/df is piecewise constant and discontinuous at every node.
       A secant step across a node can stall or cycle. `safe_root` would still be safe there
       (it falls back to bisection), but the gain is small and the change would make any
       Fortran-vs-Julia comparison harder to attribute. Left deliberately.

-----------------------------------------------------------------------------------------------
 B6. THE RESIDUAL — what happens at every trial fO2          [_coh_derive:689, unified_residual:712]
-----------------------------------------------------------------------------------------------
     Given one trial fO2, each sink states its demand. This is the heart of the model.

     (i)   SOLID Fe³⁺        sOₑₓ = invert sfO2 at this fO2                             [:692]
     (ii)  MELT Fe³⁺         mOₑₓ = invert the Hirschmann oxybarometer at this fO2       [:693-694]
           both via [_invert_demand:676], which bisects the monotone oxybarometer and
           SATURATES AT THE BOUNDS when the target lies outside the achievable range:
             ? floor reached -> that sink holds ~nothing and stops buffering
             ? cap reached   -> that sink is full and stops buffering
           This is the ONLY legitimate way fO2 equality can fail.

     (iii) FLUID + CARBON    one joint solve, [coh_state:544]  — expanded in B7        [:697]
     (iv)  MELT CO₂          XCO₂ from that solve -> carbonO = Φ·XCO₂/(1-XCO₂)          [:699-700]
     (v)   SOLID CARBONATE   carbO from that solve                                      [:703]

     RESIDUAL = sOₑₓ + mOₑₓ + carbonO + carbO + fₑₓ  -  1                               [:708, unified_residual:712]

     ! Every term is a fraction of TOₑₓ, so the equation is literally "the shares add to 100 %".

-----------------------------------------------------------------------------------------------
 B7. THE FLUID AND CARBON SUB-SOLVE                          [coh_state:544]
-----------------------------------------------------------------------------------------------
     Called once per trial fO2. Determines simultaneously: how much free carbon exists, which
     mineral hosts it, the fluid's composition, and how much oxygen the fluid takes or gives.

     a) EQUILIBRIUM CONSTANTS                                 [reaction_Ks:366, called :547]
        C+O₂=CO₂, C+½O₂=CO, H₂+½O₂=H₂O, C+2H₂=CH₄ from HP98 data.
        ? WHICH CARBON POLYMORPH: whichever of graphite/diamond is lower in Gibbs energy at
          this (T,P).                                                                   [:619]
          ! Using graphite unconditionally past its ~2-5 GPa stability limit exaggerates its
            pressure destabilisation and collapses the saturation ceiling.

     b) THE CARBON-ACTIVITY CEILING — the key decision                                  [:555-556]
        fE = EMOG(D), the graphite/diamond <-> carbonate boundary   [logfO2_EMOG:617]

            f < fE   graphite/diamond is the stable solid host  ->  aC_cap = 1
            f > fE   carbonate is the stable solid host         ->  aC_cap = 10^(fE - f)

        The second branch is the carbonate equilibrium itself: with carbonate present,
        aC = f_EMOG/fO2, so carbon activity FALLS as conditions oxidise.

     c) OUTER LOOP over fugacity coefficients (6 passes)                                [:561-571]
        φ frozen -> solve aC -> get composition -> refresh φ from that composition.
        ? WHY NESTED THIS WAY: the aC solve is pure arithmetic, but each φ refresh costs an
          equation-of-state root-find. Freezing φ during the aC bisection keeps the expensive
          EOS at one evaluation per outer pass instead of one per aC trial (~3 ms/case total).

     c2) SOLVE THE HYDROGEN SPLIT, when melt_H2 or melt_H2O is on   [_solve_hydrogen]
        Runs FIRST inside each phi pass, because it moves molH_fl and the carbon balance reads it.
        TWO BRANCHES, and which applies is decided by a test rather than assumed:
            SATURATED       (m + meltH(m, lam=1))/molH_tot - 1 = 0     bracket [0, molH_tot]
            UNDERSATURATED  meltH(0, lam)/molH_tot - 1 = 0             bracket lam in (0, 1]
        ? THE TEST is meltH(0, lam=1) >= molH_tot - the melt's SATURATED demand already exceeds the
          whole inventory, so no free fluid can exist and the fugacities must fall instead.
        ? lam SCALES BOTH FUGACITIES TOGETHER so f_H2O/f_H2 = K3*sqrt(fO2) is untouched: it is the
          fluid that has vanished, not the equilibrium.
        ? THE COUPLING RUNS BOTH WAYS in the saturated branch, which is why it needs a solve at all:
          the melt takes what the fugacities dictate, while the fluid's own hydrogen sets how much
          carbon it holds, hence aC, hence the speciation, hence f_H2 and P_H2O.
        ! MELT H2O IS IN THE HYDROGEN BALANCE ONLY. It carries zero excess oxygen by the reference
          state, so it never appears in the oxygen residual - that is what lets it be an amount
          rather than a sixth sink. Melt H2 is the opposite and IS a sink.
        ! The two inner solves are ALTERNATED, not nested: each is a 1-D bracketed root find and
          the existing phi loop couples them. No third nesting level was added.

     d) SOLVE aC FOR CARBON MASS BALANCE                      [_solve_aC:525]
        (SUMMARY ONLY — the full account of this solve is PART C)
        ? aC = aC_cap  if the demand at the cap is still below the carbon available
                       -> a SOLID CARBON PHASE EXISTS and holds the remainder            [:527-528]
        ? otherwise    bisect in log₁₀aC over [-300, cap]                                [:531-537]
                       -> NO solid carbon; every atom is dissolved in melt + fluid
        ! The bracket must reach far below any plausible aC: the melt's buffer coefficient can
          exceed 1e40 at high fO2, so a shallower floor leaves carbon over-committed.
        ! Demand comes from [_carbon_demand:507] = melt CO₂ + fluid carbon. With NO free water
          the fluid does not exist, so its validity must not veto the balance.           [:513]

     e) SPECIATION                                            [_coh_reaction_step:485]
        aC multiplies all three carbon reactions; a quadratic in XH₂ closes on ΣX = 1.
        ! Solved in the numerically stable form 2c/(b+√disc): the textbook root divides by a
          coefficient that vanishes as aC -> 0 and silently returns zero fluid.          [:497]

     f) HOW MUCH FLUID                                                                  [:573-578]
        Composition is intensive — it says nothing about quantity. The AMOUNT is fixed by
        hydrogen conservation against the water budget Mh.

     g) SPLIT THE SOLID CARBON                                                          [:582-592]
        nC_solid = whatever melt and fluid did not take, but ONLY while aC sits at its ceiling.
        ? WHICH HOST: ramped over wEMOG = 0.25 log units around fE rather than switched.
          ! A hard switch is a step in oxygen demand (2 O per carbon converted) that would put
            a jump back into the residual and destroy the root. Real carbonate is a
            magnesite-dolomite-calcite solution, so the boundary genuinely is smeared.
        carbO = 2·nC_carb·mm.O/TOₑₓ     (carbonate carries 2 excess O per carbon)

     h) THE FLUID'S NET OXYGEN DRAW                                                     [:594-598]
             netO per mole of fluid = 2·XCO₂ + XCO - 2·XCH₄ - XH₂

        ! THIS IS WHERE THE REFERENCE STATE OF B2 PAYS OFF. H₂O contributes ZERO — it is the
          reference. CO₂/CO consume excess oxygen; CH₄/H₂ RELEASE it, because making methane
          out of water frees the oxygen that water carried in.
        ? A NEGATIVE RESULT IS PHYSICAL, not an error: a reduced fluid donates oxygen to the
          rock, and the mass balance absorbs that naturally.
        Bounded to ±1e3: |value| > 1 already exceeds the whole budget, so magnitude beyond
        that carries no information and would only distort the bracket search.

-----------------------------------------------------------------------------------------------
 B8. READ OFF THE FINAL STATE                                [partition_Oₑₓ:822-827]
-----------------------------------------------------------------------------------------------
     _coh_derive is called ONCE MORE at the converged fO2, and the reported state is that one.
     ! Deliberate: the reported numbers are then guaranteed to be the state the residual
       actually saw, not a recomputation that might drift from it.

-----------------------------------------------------------------------------------------------
 B9. DIAGNOSE THE REGIME                                     [classify_regime:720]
-----------------------------------------------------------------------------------------------
     ! REPORTING ONLY. The solve is regime-free, so a label can never disagree with what was
       solved — unlike a branching solver, where the two can drift apart.

     Tested in this order:
       capacity_exceeded              no fO2 reaches the budget even with every sink full
       oxidant_exhausted             both Fe³⁺ sinks at their caps
       solid_saturated               solid at its cap, no longer tracking fO2
       melt_saturated                melt at its cap
       solid_depleted                solid holds ~no Fe³⁺, so it no longer buffers
       melt_depleted                 melt holds ~no Fe³⁺
       carbonate_graphite_buffered   both solid carbon hosts coexist — sitting on EMOG(D)
       carbonate_saturated           carbonate is the host; graphite/diamond gone
       carbon_undersaturated         no solid carbon at all; every atom dissolved
       buffered                      nothing pinned, graphite/diamond present — the normal case

     Also returns fO2_equal and `pinned`, so the report can state whether the equality that
     underpins the model actually held, and if not, whether it was allowed to fail.

-----------------------------------------------------------------------------------------------
 B10. REPORT                                                 [partition_Oₑₓ:829-957]
-----------------------------------------------------------------------------------------------
     ? Shares are quoted against the pool ACTUALLY available.                           [:910-911]
       When the fluid is reducing it breaks H₂O down and adds that oxygen to the budget, so the
       pool becomes TOₑₓ + released, and the fluid appears in the pool header rather than as a
       negative row. This keeps every entry positive and the column summing to 100 %.
     Two budget tables — oxygen as fractions of TOₑₓ, carbon as fractions of TC.
     `out=true` returns both, ready to scale tracer fields.                             [:959]


===============================================================================================
 PART C — THE aC SOLVE IN DETAIL
===============================================================================================

 C.0  WHY aC EXISTS AT ALL
 -----------------------------------------------------------------------------------------------
   fO2 is the OUTER unknown. aC is the SECOND unknown, and it exists because carbon mass balance
   is a separate constraint from oxygen mass balance.

   At fixed fO2 and P-T, thermodynamics fixes the RATIOS of the carbon species. What it does not
   fix is HOW MUCH carbon there is. The equilibrium constants are written for graphite/diamond
   saturation: "C + O2 = CO2" presumes a pure carbon phase sitting there at unit activity as an
   inexhaustible reservoir. If the tracer's carbon budget cannot sustain the composition that
   presumption implies, the presumption is false.

   aC is the correction. It multiplies every carbon-bearing reaction:  [_coh_reaction_step:485]

       XCO2 = aC · K1 · fO2      / (phiCO2 · P)          C  +  O2  =  CO2
       XCO  = aC · K2 · sqrt(fO2)/ (phiCO  · P)          C  + 1/2 O2 = CO
       XCH4 = aC · K4 · phiH2^2 · P / phiCH4 · XH2^2     C  + 2 H2 =  CH4
       XH2O =      K3 · phiH2 · sqrt(fO2) / phiH2O · XH2   (carbon-free: no aC)

       aC = 1   free graphite/diamond is present and buffering
       aC < 1   NO free carbon phase; every atom is dissolved, all three species scale down together

   ! aC is therefore not a fitted parameter. It is the thermodynamic activity that makes carbon
     mass balance close, and it is solved for exactly.


 C.1  WHERE IT SITS — THE NESTING
 -----------------------------------------------------------------------------------------------
   bisect_solve                      outer bisection on log10 fO2         [bisect_solve:759]
    +- unified_residual              sum(demands) - 1                     [unified_residual:712]
        +- _coh_derive               trial fO2 -> full state              [_coh_derive:689]
            +- coh_state             fluid + carbon at that fO2           [coh_state:544]
                +- x6 OUTER phi LOOP                                      [:561-571]
                |   +- _solve_aC             <-- INNER BISECTION          [_solve_aC:525]
                |   |   +- x120 _carbon_demand                            [_carbon_demand:507]
                |   |        +- _coh_reaction_step  (pure arithmetic)     [_coh_reaction_step:485]
                |   +- _coh_reaction_step    (final composition at that aC)
                |   +- zd_fugacity           <-- the ONLY EOS call        [zd_fugacity:447, :566]
                +- split solid carbon, compute netO

   So _solve_aC runs SIX times per residual evaluation, and the residual is evaluated 30-40 times
   per case. Roughly 200 aC solves and 24,000 _carbon_demand calls per partition_Oₑₓ call.
   That count is the entire reason for the design in C.3.


 C.2  WHAT VARIES, WHAT IS FROZEN
 -----------------------------------------------------------------------------------------------
   _solve_aC(fO2, Pbar, K1, K2, K3, K4, phi, molH, nC_total, nOxideTotal, Bmelt, aC_cap, XCO2max)

   THE ONLY QUANTITY THAT VARIES INSIDE IT IS aC. Every argument is a frozen constant for the
   duration of the bisection:

     ARGUMENT       FROZEN AT                             WHY IT CAN BE FROZEN
     -------------------------------------------------------------------------------------------
     fO2            the outer bisection's current trial   aC is solved AT a given fO2, not jointly
     Pbar, K1..K4   P-T only            [reaction_Ks:366] HP98 constants; no composition dependence
     phi (7-vector) the PREVIOUS outer pass       [:561] the expensive one — see C.3
     molH           2·Mh/mm.H2O                   [:548] all H is in the fluid; never redistributed
     nC_total       Mc/mm.C                       [:549] the budget being balanced against
     nOxideTotal    melt oxide moles              [:806] melt CO2 is a mole fraction against this
     Bmelt          EMOG(D) inversion at this fO2  [invert_carbon_buffer_fO2:324, :550]
                                                          melt XCO2 the buffer wants at aC = 1
     aC_cap         min(1, 10^(fE - f))           [:556] ceiling set by the stable solid host
     XCO2max        0.3 (kwarg)                   [:544] guard on the melt branch

   ! NOTHING is recomputed from the trial aC except the speciation itself. That is what makes each
     bisection step a handful of flops.


 C.3  WHY phi IS FROZEN — THE COST ARGUMENT
 -----------------------------------------------------------------------------------------------
   zd_fugacity is Zhang & Duan (2009): a Lennard-Jones mixing pass over 7x7 species pairs, then a
   BISECTION ROOT-FIND ON VOLUME [zd_findroot:423], then 7 fugacity coefficients. Hundreds of
   flops plus an inner iteration of its own.

   If phi were refreshed inside the aC bisection the cost would be one EOS call per aC trial:

       naive     ~24,000 EOS calls per case
       as built     ~200 EOS calls per case          (~100x, and ~3 ms/case)

   The loop is therefore SPLIT:                                                    [:561-571]

       for pass in 1:6
           aC   <- bisect against FROZEN phi         (closed form, no EOS)   [_solve_aC:525]
           X    <- speciate at that aC                             [_coh_reaction_step:485, :563]
           phi  <- refresh ONCE from that composition              [zd_fugacity:447, :566]
       end

   ? WHAT THIS BUYS: the EOS is evaluated once per outer pass instead of once per aC trial.
   ! WHAT IT COSTS: _solve_aC returns the aC that is exactly right FOR THE PREVIOUS PASS'S phi.
     Self-consistency between aC and phi comes only from the outer loop converging.
   ! THE OUTER LOOP HAS NO CONVERGENCE TEST — it is a fixed 6 passes of successive substitution,
     not a solve. Well-behaved in practice (phi depends only weakly on composition after the first
     pass or two), but there is no guarantee attached to it and no diagnostic if it stalls.
     First pass starts from phi = 1 throughout, i.e. ideal gas.                     [:558]
   ! Only phi[i] values that come back finite and positive are accepted; the rest keep their
     previous value, so a failed EOS evaluation degrades rather than poisons the state.  [:567-569]

   ? WHAT PHYSICAL PROBLEM THIS SOLVES — a DIFFERENT one from carbon balance. K1-K4 are written in
     FUGACITIES (e.g. K1 = f_CO2/(aC·fO2), f_CO2 = phi_CO2·XCO2·Pbar). Leaving phi=1 throughout
     would silently solve every equilibrium as an IDEAL GAS at multi-kbar to multi-GPa pressure —
     a bad approximation that does not cancel out species-by-species. This loop is tackling
     REAL-FLUID NON-IDEALITY of the mass-action equilibria; _solve_aC is the separate piece
     handling carbon balance, at whatever phi the previous pass supplied.
   ? HOW newphi IS ACTUALLY COMPUTED — by DEFINITION, not a separate fit: phi_i = f_i/(x_i·Pbar)
     always, and zd_fugacity already built fug[i] = Pbar·exp(lng_i)·vx[i] internally, so
     `newphi = fug[i]/(vx[i]*Pbar)` [:578] reduces ALGEBRAICALLY to exp(lng_i) exactly — vx[i]
     and Pbar cancel, verified bit-for-bit even at vx[i]=1e-9. Full EOS derivation, including
     where the Lennard-Jones mixing rule enters (twice — once building the pseudo-pure mixture
     before the volume solve, once again in the fugacity formula itself): TOex_math.txt PART 4.5.


 C.4  THE DEMAND FUNCTION                                            [_carbon_demand:507]
 -----------------------------------------------------------------------------------------------
   Answers one question: AT THIS CARBON ACTIVITY, HOW MANY MOLES OF CARBON DO MELT + FLUID WANT?

   MELT                                                                             [:508-509]
       Xm      = softcap(aC · Bmelt, XCO2max)        smooth ceiling, see F.1
       nC_melt = Xm · nOxideTotal / (1 - Xm)

   FLUID — and here is the structural point:                                        [:517-518]
       THE FLUID'S SIZE IS SET BY HYDROGEN, NOT BY CARBON.

       nH       = 2·XH2O + 4·XCH4 + 2·XH2            H atoms per mole of fluid
       n_fluid  = molH / nH                          <- fixed by the water budget alone
       nC_fluid = n_fluid · (XCO2 + XCH4 + XCO)

     ? So raising aC does NOT grow the fluid. It changes its COMPOSITION, shifting mole fraction
       out of H2/H2O and into CO2/CH4/CO, which raises the carbon-per-mole-of-fluid ratio.

   MONOTONE INCREASING IN aC — this is what makes bisection legal:
       XCO2, XCO   directly proportional to aC
       XCH4        via aq2 ∝ aC, pushing more of the H2 budget into methane
       nC_melt     rises with Xm, which rises with aC
     ! Monotonicity is a PROPERTY here, not an enforcement. Unlike the solid oxybarometer (B3), it
       does not need repairing — it follows from the mass-action forms above.

   TWO GUARDS:
     ? molH <= 0  ->  return nC_melt only                                           [:513]
       With no water there IS no fluid phase. Without this guard a non-existent phase's
       composition — and its validity flag — could veto the carbon balance.
     ? speciation invalid  ->  return +Inf                                          [:516]
       Fires when XCO2 + XCO >= 1, i.e. the carbon species alone would overfill the fluid.
       +Inf is deliberate: it reads as "demand far too high", which is exactly right, and it keeps
       the function monotone so the bisection simply pushes aC down.


 C.5  THE DECISION: IS THERE A SOLID CARBON PHASE?                     [_solve_aC:527-528]
 -----------------------------------------------------------------------------------------------
   STEP 1 — TRY THE CEILING FIRST.
       aC_cap is the highest activity any stable solid host allows:                 [:555-556]

           f < fE (EMOG(D))   graphite/diamond is the host   ->  aC_cap = 1
           f > fE             carbonate is the host          ->  aC_cap = 10^(fE - f)

       Evaluate the demand there. If it is AFFORDABLE (d1 <= nC_total) there is carbon left over
       after melt and fluid have taken theirs, so a SOLID CARBON PHASE PRECIPITATES and buffers aC
       exactly at the cap. Return immediately — no bisection needed.

   STEP 2 — OTHERWISE BISECT.
       Demand at the cap exceeds the budget, so no solid carbon can exist: melt and fluid want
       more carbon than there is. aC must fall until they want exactly what is available.
       A root is then guaranteed inside the bracket.

   ! THE ORDER MATTERS. Testing the cap first is not an optimisation — it is how the model decides
     between the two physical states. There is no separate "is graphite stable?" test anywhere.

   ? WHY THE CAP FALLS ABOVE fE, PHYSICALLY. aC_cap = 10^(fE-f) is DERIVED, not fitted: generalise
     the EMOG(D) reaction quotient (B, the carbonate boundary) to a variable carbon activity while
     holding carbonate+silicates at unit activity, and solving ΔG_rxn=0 gives exactly this form —
     full derivation in TOex_math.txt PART 3.2. Physically (Le Chatelier): raising fO2 past fE
     pushes 2MgCO3+Mg2Si2O6=2Mg2SiO4+2C+2O2 backward, toward CONSUMING free carbon to make MORE
     carbonate, so any carbon activity consistent with carbonate+silicates being in equilibrium at
     that fO2 is forced down by exactly this amount.
   ? WHY aC KEEPS APPEARING AT ALL ONCE CARBONATE (NOT GRAPHITE) IS THE REAL HOST. K1,K2,K4 are
     always built from GRAPHITE's Gibbs energy (B, reaction_Ks) — there is no separate carbonate-
     referenced version. Above fE, aC_cap is best read as a FORMAL BRIDGING VARIABLE: "the
     graphite-referenced carbon fugacity this carbonate-buffered environment is consistent with",
     not literal residual graphite. That is what lets ONE set of equations serve as the carbon
     speciation law continuously on both sides of the EMOG(D) transition.
   ? WHAT "aC DROPS" MEANS FOR THE CARBON DEMAND, C.4. D(aC) is a SOLUBILITY LAW, not a preference:
     D(aC_cap) is "how much melt+fluid would hold AT SATURATION". If nC_total can't reach that, the
     system cannot be saturated (there is nothing to precipitate — a solid phase with negative
     mass is not physical), so the ONLY self-consistent activity is the lower one where D(aC) =
     nC_total exactly. The demand falls as a CONSEQUENCE of D being monotone and aC being forced
     down by insufficient carbon — not because dissolved carbon is somehow "cheaper" than a solid
     phase. Same logic as a solute below its solubility limit: all of it dissolves, no crystal
     forms, and the solution's activity simply sits below saturation.


 C.6  THE BISECTION                                                    [_solve_aC:531-537]
 -----------------------------------------------------------------------------------------------
       nC_total <= 0  ->  return 0.0        no carbon at all, no carbon species        [:526]
       lo, hi = -300.0, log10(aC_cap)       bracket in LOG10 aC
       safe_root on  g(u) = log10( demand(10^u) / nC_total )

   ? WHY LOG SPACE IN aC: demand spans hundreds of decades in aC. Linear bisection would spend
     every iteration in the top decade and never resolve the rest.
   ? WHY LOG SPACE IN THE RESIDUAL TOO — this is what makes Newton pay. At small aC the demand is
     PROPORTIONAL to aC, so log-log is a straight line and the secant lands on the root almost
     immediately. On the raw residual demand/nC_total - 1 the same bracket is exponential over 300
     decades, regula falsi crawls in from the bottom, and the measured cost was 59-94 evaluations
     - barely better than the 120 it replaced. In log space it is 16-17, with |F| ~ 1e-16.
   ? WHY ILLINOIS AND NOT PLAIN NEWTON: the demand has two kinks in it, the melt XCO2 softcap and
     the aC_cap clamp. A bracketed method cannot be thrown by either; an unbracketed Newton can.

   ! WHY THE FLOOR IS -300 AND NOT -40: at high fO2 the melt's buffer coefficient Bmelt can exceed
     1e40, so a shallower floor leaves carbon still over-committed AT THE BRACKET EDGE. This was a
     real failure — carbon over-committed by a factor of 375 — not a hypothetical.

   ! THERE IS NO SIGN CHECK AT lo. If demand exceeded the budget even at aC = 1e-300 the loop
     would silently return the floor and carbon balance would be violated. That is caught
     downstream by the carbon-closure check, not here. Worst observed across the sweep: 4.6e-15,
     so the floor has never been reached in practice.

   ! MEASURED, 48-case sweep, melt_H2 off: fO2 BIT-IDENTICAL to the old 120-step bisection, aC to
     7e-13, and the whole driver 31 % faster (2.66 -> 1.83 ms/case). The remaining cost is the
     Zhang & Duan EOS, not the root finds.


 C.7  WHAT THE ANSWER MEANS DOWNSTREAM                                              [:582]
 -----------------------------------------------------------------------------------------------
   The returned aC carries TWO DISTINCT PHYSICAL STATES, separated by one test:

       solid_present = nC_total > 0  &&  aC >= aC_cap·(1 - 1e-9)

     PINNED AT THE CAP  ->  a solid carbon phase coexists.
                            nC_solid = nC_total - nC_melt - nC_fluid  is what it holds,
                            then split graphite vs carbonate by the logistic ramp across fE
                            (B7g).  Contributes carbO = 2·nC_carb·mm.O/TOₑₓ to the oxygen budget.
     BELOW THE CAP      ->  carbon-undersaturated. NO solid carbon at all, nC_solid = 0, and
                            carbon mass balance closes EXACTLY BY CONSTRUCTION.

   ! This is why carbon closure is exact rather than enforced: in one branch the solid absorbs the
     residual by definition, in the other the bisection drove the residual to zero.

   aC then feeds back into the OUTER fO2 residual through three channels:
       carbonO  melt CO2 oxygen         via XCO2_melt = softcap(aC·Bmelt, XCO2max)     [:577]
       carbO    solid carbonate oxygen  via nC_solid -> nC_carb                        [:592]
       fₑₓ      fluid net oxygen        via the speciation aC produced                 [:597]
   -> so every step of the outer fO2 bisection re-runs the entire C.1 stack.


 C.8  WHAT TO WATCH
 -----------------------------------------------------------------------------------------------
   1. aC printed as exactly 1.0 with `graphite/diamond present` is the saturated branch;
      any other value means the undersaturated branch ran and the bisection set it.
   2. aC pinned at a cap far below 1 (e.g. 1e-5) means CARBONATE is the host and conditions are
      several log units above EMOG(D) — not that carbon is scarce.
   3. A carbon-closure miss above ~1e-12 is the signature of the -300 floor being hit (C.6).
   4. phi lagging the composition by one pass (C.3) is a second-order error in the fluid, and the
      only place ∂phi/∂fO2 is dropped anywhere in the model.

===============================================================================================
 PART F — WHERE THE MODEL CAN STILL BE WRONG
===============================================================================================
  These are logic-level caveats. For the quantitative validation record see TOex_bench.txt.

  1. XCO2max = 0.3 [coh_state kwarg] is INVENTED. It does NOT replace the EMOG(D) buffer: the
     buffer still sets melt XCO₂ from P-T-fO2 (XCO₂ = aC·Bmelt, B6/B7), and the cap only bounds
     where that inversion stops describing a silicate melt. Needed because at EMOG(D) the buffer
     already asks for XCO₂ ~ 0.8-2.1, and nC_melt = X·nOx/(1-X) diverges as X -> 1.
     Measured: the raw buffer value never exceeds the cap across the 1296-case sweep (worst
     raw/cap = 0.994), so it is insurance near the carbonate boundary, not an active constraint.
  2. wEMOG = 0.25 [coh_state:544 kwarg] is invented, though physically motivated.
  3. Above the tabulated Fe³⁺ range the solid fO2 is EXTRAPOLATION, not MAGEMin — it follows the
     oxybarometer's form and cannot capture a phase change MAGEMin would have found. Flagged in
     the report when it engages.
  4. The isotonic repair alters MAGEMin's output. It is the least-squares monotone fit, so the
     distortion is minimal, but a genuinely non-monotonic solid fO2 is a signal worth reading —
     the warning says so.
  5. ∂φ/∂fO2 is dropped: the fugacity-coefficient loop is frozen during the aC solve. Second
     order, but it means φ lags the composition by one pass. The outer φ loop is moreover a fixed
     6 passes of successive substitution with NO convergence test and no diagnostic if it stalls.
     See C.3.
  6. The C-O-H fluid excludes C₂H₆ by design; that carbon reappears as CH₄.
  7. MELT H2O USES Sun & Yao (2026), WHOSE H2O HALF STOPS AT 2 GPa. Their 1 bar-6 GPa headline is
     the CO2 half; the H2O experiments reach only 2 GPa, and the a2*P^2/T term diverges above it -
     142 wt% at 3 GPa, 4.99e4 wt% at 6 GPa on TOex's own basaltic melt. P is clamped to 2 GPa at
     fixed X_H2O, so above that depth the melt's water capacity STOPS RISING WITH PRESSURE, which
     is known to be wrong in direction. Same posture as the ZD09 clamp; it bounds the error rather
     than pretending to model it.
     ? Chosen over Moore et al. (1998) regardless: Moore stops at 3 kbar, i.e. 0.3 GPa, so it is
       out of range for essentially the whole mantle. Sun & Yao also resolves molecular vs OH,
       which is what makes the lam branch meaningful.
  8. THE FUGACITY-COEFFICIENT LOOP IS THE ACCURACY FLOOR, not the root finds. Measured at f = -8,
     T = 1600 K: 1 pass (ideal, phi = 1) against convergence gives X_CO2 0.182 -> 1.5e-4 at 5 GPa,
     a factor of 1200, with X_CH4 0.019 -> 0.294 and aC 0.016 -> 0.407. At 0.1 GPa the same
     comparison moves X_H2O by 2 %. So a solution IS reached without the loop, but at mantle
     pressure it is a different fluid entirely. Convergence is geometric at ~1e-2 per pass, so the
     default 6 passes leave ~2e-4 in the mole fractions - above the outer solve's 1e-8 tolerance.
  9. MELT H₂ IS THE FIRST TERM SENSITIVE TO THE *ABSOLUTE* fO2 SCALE, and this is the largest
     caveat on it. Every earlier sink is relative — offsets within sb24 cancel — but melt H₂ takes
     f_H2, which is set by the absolute fO2 through H₂ + ½O₂ = H₂O. TOex's internal IW sits
     +1.49 log units above the literature IW at 1 bar / 1673 K (measured), which understates f_H2
     by ~10^0.75 ≈ 5.6x and so understates dissolved H₂ by about the same factor.
     ! THE SPECIATION ITSELF IS NOT AT FAULT. Evaluated AT the literature IW the O-H fluid gives
       X_H2 = 52.6 / 77.9 / 91.8 % at IW / IW-1 / IW-2, against Hirschmann's 48 / 74 / 90 %. The
       whole discrepancy is the buffer position, i.e. the known absolute offset.
     ! And the H₂ LAW is independently confirmed: basalt with pure H₂ at 1 GPa gives 0.603 wt% H₂
       against the paper's ~0.57, a 6 % miss inside their own ±50 % FTIR calibration uncertainty.
     ⇒ This raises the priority of the absolute-offset problem from cosmetic to quantitative.

===============================================================================================
 PART G — DEGENERATE INPUTS: ϕ = 0 AND ϕ = 1
===============================================================================================

  The melt fraction ϕ scales the melt sink and, through Ms = Mt·(1-ϕ), the solid sink. At the two
  endpoints one of the two Fe³⁺ hosts DOES NOT EXIST, and "absent" is not the same as "empty":

      EMPTY  a phase is present but holds ~no Fe³⁺. It still has an oxybarometer, and its fO2
             reading is meaningful — it is simply pinned at its floor.
      ABSENT a phase has zero mass. It has NO oxybarometer. Any fO2 attributed to it is fictitious
             and must not be compared against the other phases.

  WHAT THE CODE DOES AT EACH ENDPOINT

   ϕ = 0  (no melt)                                                    regime :solid_only
      Mf = 0  ->  nOxideTotal = 0  ->  Φ = 0  and  maxmOₑₓ = 0                     [:170, :807]
      -> melt CO2 contributes exactly zero oxygen (Φ = 0 nulls carbonO)            [:700]
      -> melt carbon demand is zero (nC_melt = Xm·0/(1-Xm))                        [:509]
      -> the melt Fe³⁺ sink has zero capacity and is flagged absent                [:725]
      The carbon budget therefore splits between fluid and solid host only, and the aC solve of
      Part C runs unchanged — it simply sees nOxideTotal = 0.

   ϕ = 1  (no solid)                                                   regime :melt_only
      Ms = 0  ->  the solid oxybarometer's x-axis is scaled by Ms/TOₑₓ, so the whole grid would
      collapse to a single degenerate knot at zero.
      ? MAGEMin IS SKIPPED ENTIRELY and a placeholder returned                     [:216]
        This is also the one place the expensive step is avoidable: MAGEMin is ~all of the cost.
      -> maxsOₑₓ = 0, the solid sink is flagged absent                             [:725]

   THE GUARD THAT MAKES BOTH WORK                                      [_invert_demand:677]
      A zero-capacity sink gives _invert_demand the bracket [lowclip, -lowclip] — INVERTED, hi<lo.
      ! Bisecting an inverted bracket produces NEGATIVE loadings, which then reach the solid
        oxybarometer's low-end extrapolation as log10(negative -> 1e-300) - log10(0) = +Inf.
        Caught by nancheck, but only as a crash. The guard `hi <= lo -> return lo` removes the
        path entirely: a zero-capacity sink returns its floor and holds nothing.

   REPORTING                                                                       [:843, :866-874, :888, :899-901]
      An absent phase prints `ABSENT` rather than a number, the fO2-equality check is skipped for
      it (a fictitious reading cannot agree or disagree with anything), and distance-to-cap prints
      `n/a` rather than dividing by zero. `pinned` is set, so the equality check downstream cannot
      raise a spurious warning.

   IS THE ANSWER PHYSICALLY VIABLE?
      YES at both endpoints, and for the right reason: with one Fe³⁺ host gone the shared-fO2
      construction still holds among the phases that remain (the other Fe³⁺ host, melt CO2, solid
      carbonate, C-O-H fluid), and the residual is unchanged — one of its five terms is simply
      identically zero. fO2 equality is not "skipped"; there is only one Fe³⁺ oxybarometer left to
      define it, which is exactly the univariant situation the model describes.

   ! WHAT CHANGES PHYSICALLY: with only one Fe³⁺ host, capacity_exceeded becomes much more likely.
     At ϕ = 1 the melt's stoichiometric ceiling is maxmOₑₓ ≈ 0.4 for TOex = 2 wt%, so the melt
     alone cannot absorb the budget and the model correctly reports ~60 % unplaced. That is the
     intended diagnosis, not a solver failure.
